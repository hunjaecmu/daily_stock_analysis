# ETF 로테이션(규칙 기반 듀얼 모멘텀)

`python main.py --etf-rotation`은 미리 정해 둔 ETF 묶음을 바탕으로 **최신 리밸런싱 신호**와 **규칙 백테스트 리포트**를 만듭니다. 전체 과정은 순수 규칙 계산이며, LLM을 호출하지 않고 AI 설정도 필요 없습니다.

이 기능은 중국 본토 거래소의 A주 ETF 데이터를 기준으로 동작합니다.

## 규칙

1. **리밸런싱일**: 매주(또는 매월) 마지막 거래일 장 마감 후 신호를 계산하고, 다음 거래일 종가에 실행합니다. 신호가 나온 날의 가격으로 체결하지 않아 미래 정보를 쓰는 문제(look-ahead bias)를 막습니다.
2. **상대 모멘텀**: 최근 `ETF_ROTATION_LOOKBACK_DAYS` 거래일 동안의 상승률로 위험 자산 풀의 ETF 순위를 매깁니다.
3. **절대 모멘텀**: 상승률이 양수인 ETF만 고를 수 있습니다. 한 자리는 `1/ETF_ROTATION_TOP_N` 비중이며, 채우지 못한 자리는 방어 자산 `ETF_ROTATION_SAFE_ASSET`으로 돌립니다. 방어 자산이 설정되지 않았거나 쓸 수 없으면 현금(수익률 0)으로 처리합니다.
4. **교체 버퍼**: 이미 보유한 ETF가 여전히 조건을 만족하고, 모멘텀이 마지막으로 뽑힌 자리보다 `ETF_ROTATION_SWITCH_BUFFER_PCT`%p 이하로만 뒤처지면 계속 보유합니다. 잦은 교체를 줄이기 위해서입니다.
5. **조합이 바뀔 때만 거래**: 선택된 조합이 그대로면 아무 거래도 하지 않으며, 비중이 흐트러져도 다시 동일 비중으로 맞추지 않습니다.
6. **거래 비용**: 리밸런싱마다 `회전율 × ETF_ROTATION_COST_BPS`만큼 차감합니다. 현금으로 들어가고 나오는 부분은 회전율에 넣지 않습니다.

계산에는 수정주가(전방 수정, 前复权)를 명확히 쓰는 A주 ETF 데이터 경로만 받습니다. Efinance, AkShare, Baostock, 그리고 `forward`로 설정한 TickFlow이며, 이들 소스의 기존 우선순위와 실패 시 전환 순서를 그대로 따릅니다. Tushare, Pytdx, 전방 수정이 아닌 TickFlow는 이 명령의 대체 소스로 쓰지 않습니다. 쓸 수 있는 소스가 없으면 경고를 분명히 내고 해당 종목을 빼며, 수정되지 않은 가격을 쓸 수 있는 데이터로 취급하지 않습니다. 호출하는 쪽에서 시세 서비스를 주입한다면 돌려주는 DataFrame에 `attrs["price_adjustment"]="forward"`를 선언해야 합니다. 이 제약은 ETF 로테이션에만 적용되며, 일반 종목 분석의 데이터 소스 순서는 바꾸지 않습니다.

위험 자산 풀 가운데 아직 상장하지 않았거나 과거 데이터가 부족한 ETF는 `LOOKBACK`일만큼 데이터가 쌓이기 전에는 순위에 들어가지 않습니다. 짧은 공백은 모멘텀 계산 전에 최대 5개 봉까지만 채우며, 당일 실제로 유효한 종가가 없는 ETF는 그날 순위에서 빠집니다. 매개변수 탐색과 주 백테스트는 같은 원본 시세를 쓰며, 공백을 다시 채우지 않습니다.

시세가 없는 날에는 사거나 팔 수 없습니다. 거래해야 하는 종목에 그날 유효한 시세가 없으면 그 리밸런싱을 건너뛰고 기존 보유를 유지한 채 다음 예정 리밸런싱일을 기다립니다. 공백 기간 동안 보유 종목은 마지막 유효 시세로 평가하고, 시세가 돌아오면 마지막 시세 대비 등락을 모두 반영해 손실이 사라지지 않게 합니다. 방어 ETF에 실행일 시세가 없으면 빈 자리는 현금으로 둡니다. 이미 보유한 방어 자산에 시세가 없을 때도 가상으로 매도하지 않습니다. 방어 ETF의 최신 시세가 없으면 리포트 목표는 현금으로 표시하고 쓸 수 없다고 경고합니다. 이 목표가 다음 거래일에 체결된다는 보장은 없습니다.

데이터는 가장 최근에 **장이 마감된** A주 거래일까지 씁니다. 장중에 실행하면 아직 마감되지 않은 당일 봉은 버립니다.

시세는 실제 A주 거래일 달력에 맞춰 그 마감일까지 정렬합니다. 모든 종목에 시세가 없는 거래일(끝부분 공백 포함)도 남겨 두며, 주말이나 공휴일을 거래일로 보지 않습니다. 월요일에 시세가 없어도 지난주 매수를 화요일로 미루지 않고, 금요일에 시세가 없어도 목요일로 당겨 주말 신호를 만들지 않습니다. 과거 거래일 달력을 쓸 수 없거나 지원 범위를 벗어나면 오류를 분명히 내고 로테이션 리포트 생성을 멈춥니다. 시세 날짜를 거래일 달력 대신 쓰지 않기 위해서입니다.

## 사용법

```bash
python main.py --etf-rotation              # 리포트를 만들고 설정된 채널로 알림 발송
python main.py --etf-rotation --no-notify  # 로컬 리포트만 생성
```

리포트는 `reports/etf_rotation_YYYYMMDD.md`에 저장되며(날짜는 데이터 마감 거래일, 끝부분의 시세 없는 날 포함), 다음 내용을 담습니다.

| 항목 | 내용 |
| --- | --- |
| 데이터 경고 | 데이터 수집 실패, 과거 데이터 잘림, 하루 이상 등락(액면분할이나 수정주가 누락 의심), 여러 데이터 소스 혼용 |
| 최신 신호 | 현재 규칙상 보유 종목, 최신 종가로 계산한 목표 보유 종목, 리밸런싱 필요 여부, 모멘텀 순위. 최신 종가가 이번 주(이번 달) 마지막 거래일이 아니면 목표 보유 종목은 참고용이며, 거래일 달력을 쓸 수 없으면 확인할 수 없다고 표시합니다 |
| 백테스트 성과 | 전략과 "위험 자산 풀 동일 비중 보유(매일 리밸런싱, 비용 미차감)"를 누적 수익률, 연환산 수익률, 변동성, 샤프 지수(무위험 이자율 0), 최대 낙폭, Calmar로 비교합니다. 두 곡선 모두 전략이 처음 포지션을 잡은 날부터 계산합니다 |
| 연도별 수익률 | 해마다 동일 비중 기준과 비교합니다. 처음과 마지막 해는 1년이 다 차지 않을 수 있습니다 |
| 매개변수 안정성 검사 | 모멘텀 기간만 바꿔(20~200일, 현재 설정한 기간은 항상 포함) 같은 구간에서 연환산 수익률, 낙폭, 샤프 지수를 비교합니다. 공통 구간이 1년이 안 되게 만드는 기간은 표시하지 않습니다 |
| 최근 리밸런싱 기록 | 최근 10번의 리밸런싱에 대한 신호일, 실행일, 뺀 종목과 넣은 종목 |

백테스트 가능 구간(첫 포지션일부터 최신 종가까지)이 1년이 안 되면 연환산 지표는 의미가 없으므로, 리포트에는 데이터 경고, 최신 신호, 규칙 설명만 남기고 경고에 그 이유를 적습니다.

cron이나 CI로 매주 마지막 거래일 장 마감 후 한 번 실행하는 것을 권장합니다. 이 명령은 `--schedule`과 연결되지 않습니다.

## 설정

아래 설정은 모두 선택 사항이며, 설정하지 않으면 기본값을 씁니다.

| 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `ETF_ROTATION_POOL` | `510300,510500,159915,512890,513100,518880` | 위험 자산 풀. 쉼표로 구분하며 중복은 자동으로 제거합니다. 기본값은 차례대로 CSI 300(후선 300), CSI 500(중정 500), 창업판(ChiNext), 고배당 저변동, 나스닥, 금입니다 |
| `ETF_ROTATION_SAFE_ASSET` | `511880` | 방어 자산(머니마켓 ETF). 비워 두면 현금을 보유합니다 |
| `ETF_ROTATION_LOOKBACK_DAYS` | `60` | 모멘텀 기간(거래일), 5~500 |
| `ETF_ROTATION_REBALANCE` | `weekly` | `weekly` 또는 `monthly`. 잘못된 값이면 `weekly`로 돌아갑니다 |
| `ETF_ROTATION_TOP_N` | `2` | 동시에 보유할 최대 종목 수, 1~10 |
| `ETF_ROTATION_SWITCH_BUFFER_PCT` | `2.0` | 교체 버퍼(%p) |
| `ETF_ROTATION_COST_BPS` | `10` | 편도 거래 비용(bp). 수수료와 슬리피지를 포함합니다 |
| `ETF_ROTATION_BACKTEST_YEARS` | `8` | 백테스트에 불러올 과거 연수, 1~30 |

이 설정은 명령줄에서만 적용되며, 웹 설정 페이지에는 없습니다.

## 해석과 한계

- **수익률보다 매개변수 안정성 검사를 먼저 보세요.** 인접한 기간끼리 수익률 차이가 크다면 현재 매개변수의 결과는 주로 운에서 나온 것입니다. 1개만 보유하면 경로 의존성이 가장 크기 때문에 기본값은 2개 보유입니다.
- 추세 로테이션의 주된 가치는 **낙폭 관리**이며, 기준 지수보다 나은 성과를 보장하지 않습니다. 횡보장에서는 손절이 반복되고, 급등장(갭 상승으로 연속 상한가가 나오는 경우 등)에서는 반응이 늦습니다. 백테스트에서 동일 비중 보유보다 성과가 낮게 나오는 것은 흔하고 정상적인 결과입니다.
- **풀은 미리 정해 두세요.** 백테스트 때 나중에 "많이 오른 ETF"를 골라 넣으면 생존 편향이 생깁니다.
- **데이터 소스 대체 과정에서 과거 데이터가 조용히 잘릴 수 있습니다.** 예를 들어 둥팡차이푸(East Money) API를 쓸 수 없어 Baostock으로 넘어가면 최근 일부 데이터만 돌아올 수 있습니다. 이런 경우 "데이터 경고"에 표시되고 백테스트 구간이 짧아지므로 결론을 그만큼 할인해서 봐야 합니다. 1년이 안 되면 백테스트 부분은 아예 빠집니다.
- 리포트 저장이나 알림 발송이 실패해도 경고 로그만 남기며 명령의 종료 코드에는 영향이 없습니다. ETF 하나의 데이터 수집이 실패하거나 응답 형식이 이상하면 이번 계산에서 빼고 데이터 경고에 올립니다.
- 백테스트 결과는 미래 수익을 뜻하지 않으며 투자 권유가 아닙니다.

## 구현 위치

- `src/core/etf_rotation.py`: 순수 로직(신호, 백테스트, 지표, 매개변수 탐색). I/O는 하지 않습니다
- `src/services/etf_rotation_service.py`: 데이터 수집, 데이터 경고, 리포트 렌더링, 알림 발송
- `tests/test_etf_rotation.py`: 규칙, 미래 정보 사용 방지, 비용, 경고, 설정 파싱 테스트
